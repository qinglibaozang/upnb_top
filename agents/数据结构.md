## 规范总则

- **单一事实来源**：本文件是全部页面数据结构的权威定义。新增字段/卡片类型/数据结构，必须先在此登记，再实现代码。
- **frontmatter 字段命名**：统一小驼峰（如 `contentWidth`）；布尔用 `is`/`has` 前缀（如 `isFeatured`）；列表用复数名词（如 `tags`）。
- **字段类型**：`string` / `number` / `boolean` / `string[]` / 对象数组 `{…}[]`。必填字段标注 `必填`，可选字段标注 `可选 + 默认值`。
- **兼容原则**：新增字段必须提供默认值或优雅降级——老内容不带新字段时页面不报错。

## 内容页面（src/content/docs/）

- **存放**：`src/content/docs/` 按文件夹分类（`00.入站必读`、`01.中小学资源`、`03.AI专区`、`index.mdx`）；`astro.config.mjs` 自动扫描文件夹生成侧边栏分类，新增分类零配置。
- **通用 frontmatter 约定**：

| 字段 | 类型 | 必填/默认 | 说明 |
|---|---|---|---|
| `title` | string | 必填 | 页面标题（侧边栏与标题栏显示） |
| `description` | string | 可选 | 页面摘要 |
| `contentWidth` | string | 可选，默认 `default` | 控制正文宽度（`astro.config.mjs` 读取；取值如 `default`/`wide`/`narrow`，实现时以代码实际支持值为准） |

## 链接卡片

> 规划中：本类别用于站内多种链接卡片（如资源卡片、外链卡片、工具卡片）。具体类型与字段待功能设计确认后在此登记。设计新卡片时遵循规范总则：先登记字段表，再实现组件。

### 卡片通用字段（预留框架）

| 字段 | 类型 | 必填/默认 | 说明 |
|---|---|---|---|
| `title` | string | 必填 | 卡片标题 |
| `url` | string | 必填 | 跳转链接（站内或外链） |
| `description` | string | 可选 | 卡片摘要 |
| `icon` | string | 可选 | 图标标识（与 `src/assets/` 或图标池对应） |

> 上方为通用框架示例；每种具体卡片类型在此登记独立字段表后生效。

## 自定义页面

> 规划中：自定义页面（非文档内容页）的数据结构待功能设计确认后在此登记。定义时需包含：页面用途、数据来源（frontmatter / 配置文件 / 组件 props）、字段表、与现有导航/侧边栏的接入方式。

## 新增数据结构流程

1. 在此文件登记字段表（字段名/类型/必填/说明），遵循规范总则。
2. 确认老内容兼容（可选字段带默认或降级）。
3. 再实现组件/脚本读取逻辑。
4. 登记时同步更新"关键文件索引"（如涉及新文件）。
