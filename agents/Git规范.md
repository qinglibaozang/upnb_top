- 修改任何文件前，先运行 `git status` 检查工作区，不覆盖未提交的改动；改动前先 `git diff` 了解现状。
- 不自动 `git commit` / `git push`——除非用户明确要求提交。
- 用户要求提交时：先 `git diff` 复核全部改动，确认无遗漏、无无关文件；提交信息用约定格式（`feat:` / `fix:` / `docs:` / `chore:` 前缀 + 中文描述），一次提交一个逻辑变更，不混入无关改动。
- 不删除用户未要求删除的文件；误建的垃圾文件（如 Windows 的 `nul`）删除前向用户说明。
- 提交被 pre-commit 钩子（tsc 检查）拦截时：先判断错误是否与本次改动相关；无关的既有错误向用户说明后，经用户同意再用 `--no-verify` 提交，不擅自绕过。
